# engine/reflect — runtime reflection and serialization

`helios::reflect` (CMake target; C++ namespace `helios::refl`, headers `helios/reflect/*.h`) is the
runtime half of the schema system (02 §3.6, §3.7; ADR-004). Code generated by
[helios-schemac](../../tools/schemac/README.md) registers a `TypeInfo` per schema type and
specializes the compiled codecs; engine-internal types can be reflected by hand with
`StructBuilder`. Everything generic — JSONC, tagged binary, property paths, diff/patch, record
files, the future inspector — works on any object known only by its `TypeInfo`.

Depends on `helios::core`, `helios::math` and yyjson (private). Headless (servers and tools use it).

> **Namespace:** the spec writes `helios::reflect`; `engine/math` already declares the function
> `helios::reflect(v, n)`, so the namespace is `helios::refl` (see the schemac README,
> "Deviations").

## Usage

```cpp
#include "helios/reflect/reflect.h"
using namespace helios::refl;

// Typed (compiled codecs, no virtual dispatch):
std::string text = toJson(hull);                         // canonical JSONC
auto back = fromJson<ShipHullDef>(text);                 // Result<ShipHullDef>
std::vector<helios::u8> bytes = encodeTagged(hull);
auto again = decodeTagged<ShipHullDef>(bytes);

// Type-erased (editor, tools):
const TypeInfo* t = TypeRegistry::global().find("sample.ship.ShipHullDef");
Value v(*t);                                             // default-constructed object
ReadCtx ctx;
fromJson(*t, v.data(), text, ctx);
auto force = getJson(*t, v.data(), "thrusters[#f0791eb9c3df1ff7]/maxForce");  // key prefix ok
setJson(*t, v.data(), "handling/yawRate", "12.5");

// Undo / prefab overrides:
Patch p = diff(before, after);        // [{"op":"set","path":"thrusters[#…]/maxForce","value":1}, …]
apply(copyOfBefore, p);               // == after

// Replicated components (generated Mut<C>):
Mut<Health> m(health, &repDirty.componentMask, 1ull << componentIndex);
m.setMax(120.0f);                     // sets the field's dirty bit only if the value changed
```

Reflecting an engine type without a schema:

```cpp
HELIOS_REFLECT_TYPE(engine::DebugSettings);               // header, global scope
const helios::refl::TypeInfo& helios::refl::TypeOf<engine::DebugSettings>::get() noexcept {
    static const TypeInfo* info = StructBuilder<engine::DebugSettings>("engine.DebugSettings")
                                      .field("drawGrid", &engine::DebugSettings::drawGrid)
                                      .field("gridSize", &engine::DebugSettings::gridSize, {.id = 5})
                                      .build();
    return *info;
}
```

Builder types use the reflection walker for their codecs; generated types have compiled codecs.
Both produce identical bytes and text (cross-checked by the tests on every sample type).

## Behaviour worth knowing

- **Equality** is value equality with bitwise floats (NaN == NaN, -0 != +0): "serializes the
  same". `isDefault` compares with the schema defaults; writers omit default-valued fields.
- **Readers** start from default values, skip unknown tagged fields, warn on unknown JSON members
  (error with `ReadCtx::Options::strictUnknownFields`), accept `@was` names, comments, trailing
  commas and the bare forms of references (`"guid:"`, `"ent:"`, `"loc:"` prefixes are optional).
  Nesting depth is limited (tagged: 64 messages; JSONC: `kMaxJsonDepth` = 128 arrays/objects,
  checked iteratively at parse time, so recursive types such as `Node { kids: list<Node> }` cannot
  overflow the stack) and all reads are bounds-checked; corrupt input yields
  `ErrorCode::Corrupt`/`ParseError`/`LimitExceeded`, never UB (fuzzed in the tests). Tagged strings,
  Names and tags must be valid UTF-8. When an object has both a field's current name and an `@was`
  alias, the current name wins (any member order).
- **Property paths** escape `]` and `\` inside brackets; a map key starting with `#` is written
  `[\#…]` and the empty map key `[]`, so every diff path parses back. `@keyed(field)` segments
  compare canonical key text (`[#01]` finds the element with key `1`).
- **Keyed lists** carry a GUID per element (`"$key"` in JSON); diffs address elements by key,
  so edits and overrides survive reordering. `@keyed(field)` lists key by a field instead.
- **Registry**: `find()` is one atomic load; `add()`/`replace()` publish a new immutable snapshot.
  Snapshots live until the registry is destroyed, so returned pointers stay valid.
- **Threading**: everything is stateless or immutable except `JsonWriter`, `ReadCtx`, `Value` and
  mutable objects themselves; see each header.

## Tests

`reflect_tests` (doctest): tagged primitives (varints, zigzag, bounds, depth), JSON number
formatting (shortest round trip, f32 exactness, non-finite), every codec (vocabulary types,
containers, variants, keyed lists, widening reads, corrupt input), builder types vs. the walker,
the registry (including concurrent readers during registration), property paths, diff/patch
(including a randomized property test), record files and `Mut<C>`. The generated-code side is
tested by `schemac_tests` (tools/schemac).
