# HXL conformance corpus

The shared C++/Go conformance corpus of HXL (06 §1.2, GP-1). Every `*.jsonc` file here is run by
both interpreters:

- C++: `hxl_tests` (`engine/hxl/tests/test_corpus.cpp`, runner in `engine/hxl/tests/corpus.cpp`);
- Go: `cd services && go test ./pkg/hxl/` (`services/pkg/hxl/corpus_test.go`).

A case passes only if the compile outcome (status code **and** position), the bytecode hash and every
result match **bit for bit**. Both runners reject unknown keys, so a typo cannot silently skip a check.
GP-1 requires the Go side on `windows/amd64`, `linux/amd64` at `GOAMD64=v1` and `v3`, and `linux/arm64`,
and the C++ side on MSVC (both toolsets), clang-cl, GCC and Clang (MinGW builds but does not run). CI
covers all of these except `GOAMD64=v3` and `linux/arm64` (see `services/pkg/hxl/README.md`).

## Files

| File | Contents |
|---|---|
| `arith.jsonc` | literals, precedence, associativity, IEEE arithmetic, signed zero, infinities, NaN |
| `logic.jsonc` | comparisons, `&&`/`||`/`!`, `select`, laziness (untaken branches never read inputs) |
| `builtins.jsonc` | `min max clamp lerp abs floor ceil sqrt` incl. NaN and ±0 rules |
| `transcendental.jsonc` | `exp ln pow ^ asinh` special values and sweeps (06's `hmath` = `helios::det`) |
| `edge_floats.jsonc` | subnormals, overflow/underflow, rounding ties, cancellation |
| `inputs.jsonc` | `attr`, context fields, hierarchical `tag`, `stacks()`, `level()`, curves, missing inputs |
| `formulas.jsonc` | gameplay formulas from the plan (EVE turret hit chance, stacking penalties, capacitor recharge, …) |
| `errors.jsonc` | compile errors: every status code with its position, and the limits |
| `fma_sensitive.jsonc` | ≥ 1,000 generated vectors where fusing a multiply-add into an FMA changes the result (06 §1.2 rule 7) |
| `differential.jsonc` | generated (`HXL_CORPUS_GEN_DIFF=1 go test ./pkg/hxl/ -run TestGenerateDifferentialCorpus`): seeded random well-typed and ill-typed programs and byte-level mutations of both, with random inputs; outcomes come from Go and C++ must reproduce them bit for bit |

## Format

```jsonc
{
  "description": "free text",
  "curves": { "Xp.Level": { "keys": [0, 10], "values": [0, 100] } },   // optional, shared by the file's cases
  "cases": [
    {
      "name": "unique.case.name",          // unique across the whole corpus
      "src": "attr(self, Hp) * 0.5",       // HXL source: an expression or `formula F(a, b) = ...`
      "params": ["self"],                  // parameters of a bare expression (default ["self"])
      "expectType": "num",                 // optional CompileOptions.expectedType
      "maxCost": 100,                      // optional CompileOptions.maxCost
      "error": "E_SYNTAX", "at": "1:5",    // expected compile failure (status and line:column)
      "bytecode": "0123456789abcdef",      // FNV-1a 64 of the canonical bytecode
      "type": "num",                       // result type
      "inputs": {
        "attrs":  { "self": { "Hp": 100 } },            // attr(param, Name)
        "fields": { "ctx": { "distance": "0x1.8p+3" } }, // param.field
        "tags":   { "self": ["State.Debuff.Stun"] },    // tag(param, T) matches T and T.*
        "stacks": 2, "level": 3,
        "curves": { ... }                                // per-case curves
      },
      "expect": "0x1.8p+1",                // result; JSON booleans for bool results
      "evalError": "E_MISSING_INPUT",      // instead of "expect"
      "rows": {                            // many evaluations of one program
        "param": "v", "fields": ["a", "b"],
        "data": [["1", "2", "3"]]           // field values..., expected result
      },
      "fma": "mul_add",                    // rows are FMA-sensitive: mul_add, mul_sub, sub_mul, dot2, lerp
      "comment": "why this case exists"
    }
  ]
}
```

**Numbers** are JSON numbers or strings: exact hex floats (`"0x1.8p+1"`, `"-0x1p-1074"`; they must be
exactly representable), decimal text (zero or a normal double; correctly rounded by both languages),
`"inf"`, `"-inf"`, `"-0"` and `"nan"` (every NaN result is the canonical `0x7ff8000000000000`).

## Adding cases

Write the case with `"?"` for values you have not computed (`"expect": "?"`, `"bytecode": "?"` or a
row's last element) and run

```
cd services && HXL_CORPUS_FILL=1 go test ./pkg/hxl/ -run TestCorpusFill
```

which fills the placeholders from the Go interpreter. Then **check every filled value against an
independent reference** (exact arithmetic for + − × ÷, a multi-precision library or libm within
1 ulp for `exp ln pow asinh`), run both test suites, and review the diff. Never edit an existing
expected value to make one platform pass: a mismatch is a determinism bug (build flags, FMA fusion,
a Go conversion rule) to fix in the code.

`fma_sensitive.jsonc` is generated by `go test ./pkg/hxl/ -run TestGenerateFMACorpus` with
`HXL_CORPUS_GEN_FMA=1`; its expected values come from the IEEE definition of the unfused expression,
not from either VM, and both runners re-check with `fma()` that fusing would change every row.
